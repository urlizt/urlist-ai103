# Speech-capable Gen AI App

1. **Transcribe speech → text**
2. **Synthesize text → speech**

Typical applications include meeting transcription, captions, accessibility, and voice-enabled AI assistants.

| Task              | Direction     | Models                                                                     |
| ----------------- | ------------- | -------------------------------------------------------------------------- |
| **Transcription** | Speech → Text | `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `gpt-4o-transcribe-diarize` |
| **Synthesis**     | Text → Speech | `gpt-4o-tts`, `gpt-4o-mini-tts`                                            |

⚠️ **Model availability varies by Azure region.**

## Transcribe Speech

**Core concept**

> **Speech-to-text** = submit audio → model returns a text transcript.

### Models

* `gpt-4o-transcribe`
* `gpt-4o-mini-transcribe`
* `gpt-4o-transcribe-diarize` - identifies who's speaking
**Diarize** is the important word here: it can distinguish **who said what** in the audio.

### Python approach

Uses the **AzureOpenAI client** from the OpenAI SDK:

```python
from openai import AzureOpenAI
from pathlib import Path

# Create an AzureOpenAI client
client = AzureOpenAI(
    azure_endpoint=YOUR_FOUNDRY_ENDPOINT,
    api_key=YOUR_FOUNDRY_KEY,
    api_version="2025-03-01-preview"
)

# Get the audio file
file_path = Path("speech.mp3")
audio_file = open(file_path, "rb")

# Use the model to transcribe the audio file
transcription = client.audio.transcriptions.create(
    model=YOUR_MODEL_DEPLOYMENT,
    file=audio_file,
    response_format="text"
)

print(transcription)
```

### 🧠 Revision snapshot

> **Audio → `audio.transcriptions.create()` → text**
>
> **Client:** `AzureOpenAI`
>
> **Models:** `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `gpt-4o-transcribe-diarize`
>
> **Input:** audio file
> **Output:** transcript

# 2. Text-to-speech

Submit text to a speech model and receive an **audio stream**.

### Models

* `gpt-4o-tts`
* `gpt-4o-mini-tts`

### Key Python method

```python
from openai import AzureOpenAI
from pathlib import Path

# Create an AzureOpenAI client
client = AzureOpenAI(
    azure_endpoint=YOUR_FOUNDRY_ENDPOINT,
    api_key=YOUR_FOUNDRY_KEY,
    api_version="2025-03-01-preview"
)

# Path for audio output file
speech_file_path = Path("output_speech.wav")

# Generate speech and save to file
with client.audio.speech.with_streaming_response.create(
            model=YOUR_MODEL_DEPLOYMENT,
            voice="alloy",
            input="This speech was AI-generated!",
            instructions="Speak in an upbeat, excited tone.",
    ) as response:
    response.stream_to_file(speech_file_path)

print(f"Speech generated and saved to {speech_file_path}")
```

The **`instructions`** parameter can control characteristics such as speaking style or tone.

---

### 🧠 Important distinction

**Microsoft Foundry** → where you find/deploy/manage the model

**AzureOpenAI client** → how your Python application calls the deployed model

### ⚠️ Likely exam traps

| Question                             | Answer                          |
| ------------------------------------ | ------------------------------- |
| Speech → text?                       | `gpt-4o-mini-transcribe`        |
| Text → speech?                       | `gpt-4o-mini-tts`               |
| Identify speakers?                   | `gpt-4o-transcribe-diarize`     |
| Speech transcription API?            | `audio.transcriptions.create()` |
| Speech synthesis API?                | `audio.speech.with_streaming_response.create()`       |
| Where do you deploy the model?       | Microsoft Foundry               |
| What does `voice` control?           | Generated voice                 |
| What does `instructions` control?    | How the speech is delivered     |
| Are all models available everywhere? | **No, region matters**          |

**One-line revision:**

> **Foundry deploys the model; AzureOpenAI calls it; `transcribe` turns audio into text; `tts` turns text into audio.**
