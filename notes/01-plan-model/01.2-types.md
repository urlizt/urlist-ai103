## ** 2.1 📘 Select, deploy, and evaluate Microsoft Foundry models**

### Considerations
- Effective generative AI apps require selecting the right foundation model for the specific use case. 
- With thousands of models available, a structured discovery and comparison workflow is essential.  
- Example scenario: choosing a language model for a retail customer‑support chatbot.  
- Foundry provides access to 1,900+ models from Microsoft, Anthropic, OpenAI, Meta, and Hugging Face.
- Models can be compared using benchmarks for quality, safety, cost, and performance. 
- After selection, you deploy the model to an endpoint for application consumption. 
- Evaluation includes automated metrics and manual testing to ensure quality and safety.  
- The module teaches exploration, filtering, comparison, deployment, and evaluation workflows. 
- You can learn via video or text; text contains deeper detail.

---

## ** 2.2 📘 Model Catalog**

- Central hub for discovering and comparing AI models
- 1,900+ models; filtering is essential to find the right one
- Two model categories:  
  - Sold directly by Azure (billed via subscription)
  - Partner/community models with their own licensing
- Model cards show provider, capabilities, benchmarks, responsible AI, deployment options
- Key filters: collection, capabilities, source, inference tasks, fine‑tuning, industry
- Industry‑trained models outperform general models in domain tasks 
- LLMs = deep reasoning + complex generation; high compute cost 
- SLMs = efficient, cheaper, good for common NLP + edge devices 
- Chat completion models power conversational apps
- Reasoning models (e.g., Claude Opus) handle math, coding, science, strategy tasks 
- Specialized models:  
  - Embeddings for semantic search + RAG 
  - Image generation (GPT‑image‑1) 
  - Video generation (Sora 2) 
  - Image analysis (GPT‑4.1 multimodal) 
  - TTS (GPT‑4o‑tts) and STT (GPT‑4o‑transcribe) 
- Regional/domain‑specific models outperform general ones in specialized contexts (medical, legal, language‑specific)

## **2.3 📘 Select Models Using Benchmarks

- Benchmarks give **objective, measurable data** for model selection
- Foundry organizes benchmarks into **quality, safety, cost, performance** 
- **Leaderboard** shows top models across all metrics (quality, safety, cost, throughput)  
- **Model card → Benchmarks tab** gives detailed per‑model charts and dataset scores  
- **Quality** = accuracy, reasoning, knowledge, math, coding; normalized 0–1 index 
- **Safety** = harmful behavior resistance (ASR), toxicity detection, sensitive domain knowledge  
- **Cost** = input/output token pricing + estimated cost (3:1 ratio)  
- **Performance** = latency (mean, P50–P99, TTFT) + throughput (GTPS, TTPS)  
- Leaderboards + scenario leaderboards help pick models optimized for specific tasks (reasoning, coding, math, QA)  
- Trade‑off charts show **quality vs cost**, **quality vs throughput**, **quality vs safety** to find optimal balance   
- Side‑by‑side comparison supports comparing **2–3 models** across all benchmark dimensions

## 2.4 📘 All Deployment Types

### 📌 Overview
After selecting a model from the catalog, you deploy it to an **endpoint** so applications can access it via API.

### 🧩 Deployment Types
Microsoft Foundry supports several deployment types with different characteristics for **data residency, scaling, and billing**:

| Type | Key Feature |
|------|-------------|
| **Global Standard** | Pay-per-token, any Azure region, highest quota |
| **Global Provisioned** | Reserved throughput units (PTU), predictable high-throughput |
| **Global Batch** | 50% discount for large async jobs (≤24 hrs) |
| **Data Zone Standard** | Pay-per-token, data stays within a specific zone |
| **Data Zone Provisioned** | Reserved PTUs within a data zone |
| **Data Zone Batch** | Large async batch jobs within a data zone |
| **Standard** | Single region, pay-per-token, regional compliance |
| **Regional Provisioned** | Reserved PTUs within a single region |
| **Developer** | Pay-per-token, any region, **for fine-tuned model evaluation only** |

> 💡 The portal auto-selects the best option based on your environment and model requirements. **Global Standard** is recommended whenever possible.

### 🚀 Deployment Process (Portal)
1. **Navigate** to the model in the Model Catalog
2. **Open** the model card to review specs and supported deployment types
3. **Select Deploy** → choose **Default** (quick) or **Custom** settings
4. **Review terms** if the model requires an Azure Marketplace subscription (common for partner/community models)— Azure-sold models (e.g., GPT-4o-mini) don't need this
5. **Configure**:
   - **Deployment name** — used in API calls; default = model name
   - **Deployment type** — auto-selected
   - For **managed compute**: VM SKU + instance count
6. **Select Deploy** → lands in the **Playground** for interactive testing
7. **Verify** deployment status shows *Succeeded*


### 🧪 Test in the Playground
- **Chat interface** — enter prompts, observe responses
- Experiment with: simple questions, multi-step reasoning, specific formats, edge cases
- Adjust **system messages** to guide behavior (e.g., tone, role)
- Tune **parameters**: temperature, max tokens, top-p
- **Code tab** — view ready-to-use code samples (Python, C#, JavaScript)

### 🔑 Access Models Programmatically
To integrate into your app, you need **three key pieces** from the deployment details:

1. **Endpoint URL** — where to send requests (Foundry-specific or OpenAI v1 compatible)
2. **Authentication key** — secret key/token, **or** Microsoft Entra ID (recommended for production)
3. **Deployment name** — passed in the `model` parameter to route requests

> 🔧 The portal provides **SDKs, REST API docs, and code samples** for various languages.

### 📊 After Deployment
- Manage models from **Build → Models** in the portal
- View: config, status, endpoint URL, auth keys, monitoring metrics
- Adjust settings or delete as needed

### ✅ Key Takeaway
**Deploy → Test → Integrate** — the portal guides you through deployment, the playground lets you test without code, and the deployment details give you everything needed for programmatic access.

## 📌 Why Evaluate Models
Evaluation ensures your deployed model meets quality standards, provides accurate responses, and continuously improves. It serves four critical purposes:

| Purpose | Why It Matters |
|---------|----------------|
| **Quality Assurance** | Catches issues before production, protecting users and reputation |
| **User Satisfaction** | Ensures responses are helpful, appropriate, and consistent |
| **Continuous Improvement** | Identifies opportunities as you update prompts, add features, or retrain |
| **Compliance & Safety** | Confirms adherence to policies, avoids harmful content, respects privacy |

---

## 🧪 Manual Evaluation Approaches
Human reviewers assess responses—**time-intensive** but captures insights automated metrics miss.

| Approach | What You Do |
|----------|-------------|
| **Interactive Playground Testing** | Enter diverse prompts, observe responses, note issues (incorrect info, tone, instruction-following). Test models **side by side** with synced instructions |
| **Structured Review** | Create test cases; human evaluators rate responses on: **Relevance, Informativeness, Engagement, Accuracy, Safety** (e.g., 1–5 scale) |
| **User Studies** | Collect feedback from actual/representative users to uncover real-world issues |

---

## 🤖 Automated Evaluation Metrics
Standard metrics assess outputs automatically—**scalable, consistent, objective**.

### Built-in Evaluation Metrics
| Metric | What It Measures |
|--------|------------------|
| Groundedness	|Does the response stay within the provided source context? (RAG quality) |
| Relevance	|Does the answer address the user's question? |
| Coherence|	Is the response logically structured? |
| Fluency	Is| the language grammatically correct and natural? |
| Similarity	|How close is the output to a golden reference answer? |

### Risk & Safety Metrics (Defect Rate = % exceeding severity threshold)
- Self-harm content
- Hateful and unfair content
- Violent content
- Sexual content
- Protected material (copyright/proprietary)
- Indirect attack (jailbreak vulnerability)

> 💡 **AI-assisted evaluation**: Specify a GPT model to analyze responses and assign scores.

---

## 📊 NLP Metrics (Math-Based, No Evaluator Model)
These compare generated outputs against **ground truth** (expected/correct responses).

| Metric | Best For | Key Trait |
|--------|----------|-----------|
| **F1-score** | Classification, info retrieval | Balances precision (avoid wrong words) & recall (include important words) |
| **BLEU** | Machine translation | Compares n-grams (word sequences) |
| **METEOR** | Translation | Extends BLEU—accounts for synonyms, stemming, paraphrasing |
| **ROUGE** | Summarization | Emphasizes **recall** (covering key points > avoiding extra words) |
| **GLEU** | Sentence-level eval | Variant of BLEU |

> ⚠️ NLP metrics **work well** with definitive correct answers; **less suitable** for open-ended generation.

## 🏗️ Create Comprehensive Evaluations
Run systematic evaluations using test datasets + multiple metrics simultaneously.

### What to Evaluate
- **Model** — deployed model with prompts you specify
- **Agent** — agent's responses with user-defined prompts
- **Dataset** — pre-generated outputs already in your test dataset

### Dataset Options (for Model/Agent Evaluation)
1. **Upload new** — CSV or JSONL from local storage
2. **Use existing** — previously uploaded to your project
3. **Generate synthetic** — system creates sample data from a topic description (specify rows + prompt)

> ⏱️ Evaluation jobs run **asynchronously**, processing each row.

### Review Results
- **Aggregate scores** for selected metrics
- **Details per test prompt**

## 🔁 Iterate Based on Evaluation

### If Scores Are Low
| Action | Consideration |
|--------|---------------|
| **Prompt engineering** | Refine instructions and system messages |
| **Different models** | Try models optimized for your use case |
| **RAG integration** | Add retrieval to ground responses in your data |
| **Fine-tuning** | Train on your domain (if supported) |

> Each step grows in complexity and cost — plan accordingly.

### If Safety Metrics Show Concerns
- **Content filters** — Azure AI Content Safety
- **Prompt hardening** — add safety instructions to system messages
- **Output validation** — check responses before displaying to users

---

## ✅ Key Takeaway
**Manual testing + automated metrics + comprehensive evaluation flows** build confidence that your model performs well, serves users safely, and meets quality requirements. Establish benchmarks early and re-run evaluations after every change.
