# Create a multimodal analysis solution with Azure Content Understanding

## Module goal

Use **Azure Content Understanding** to analyse **multimodal content** and extract structured information using configurable **analyzers**.

```text
Document / Image / Audio / Video
              ↓
      Content Understanding
              ↓
           Analyzer
              ↓
      Structured information
```

## 1. What is Azure Content Understanding?

A **generative AI service** for extracting insights and data from:

- 📄 Documents and forms
- 🖼️ Images
- 🎧 Audio
- 🎥 Video

It is available through:

- Microsoft Foundry portal
- **Content Understanding Studio**
- Content Understanding API

### Key idea

Content Understanding is broader than OCR. It can **analyse content and extract meaningful structured information**.



## 2. Create a Content Understanding analyzer

An **analyzer** defines what information should be extracted from a particular type of content.

Basic workflow:

```text
Foundry resource
      ↓
Define schema
      ↓
Build analyzer
      ↓
Analyze new content
      ↓
Extract / generate fields
```

### Schema

The **schema** defines the information you want the analyzer to extract.

For example, an invoice analyzer might define:

```text
vendorName
invoiceNumber
invoiceDate
totalAmount
```

You can create the schema from a sample and use templates to accelerate development.

### Content Understanding Studio

Used to:

- Create projects
- Define schemas
- Build analyzers
- Test analyzers
- Refine schemas
- Create new analyzer versions

**Exam point:** Custom analyzer creation/testing → **Content Understanding Studio**.


## 3. Use the Content Understanding API

The API allows applications to:

- Create analyzers
- Manage analyzers
- Submit content for analysis
- Retrieve analysis results

The important pattern is **asynchronous analysis**.

```text
POST analyze
     ↓
Operation ID
     ↓
Poll operation status
     ↓
Completed
     ↓
JSON results
```

### API pattern

```text
POST
/contentunderstanding/analyzers/{analyzer}:analyze
```

Returns an **Operation ID**.

Then:

```text
GET
/contentunderstanding/analyzerResults/{operation-id}
```

until the operation completes.

### Important distinction

For content supplied as a URL:

```text
analyze
```

For binary file data:

```text
analyzeBinary
```

## 4. Multimodal analysis

The same service can process different content types.

| Content | Example use |
|---|---|
| **Documents** | Extract invoice fields |
| **Images** | Identify objects/defects |
| **Audio** | Summarize calls / detect sentiment |
| **Video** | Extract activities / summarize presentations |

This is why the module calls it **multimodal analysis** rather than simply document extraction.

### 🔑 Exam traps

- **Content Understanding ≠ image generation.**
- **Content Understanding ≠ just OCR.**
- **Analyzer** defines the processing.
- **Schema** defines what information you want extracted.
- **Content Understanding Studio** is the graphical tool for creating/testing analyzers.
- Analysis is **asynchronous**.
- `analyze` → URL input.
- `analyzeBinary` → binary file input.
- **Operation ID → poll → results**.

### 🧠 Memory hook

> **Content → Analyzer → Schema → Analyze → Operation ID → JSON**

That six-step sequence is the bit worth having burned into your AI-103 brain. Microsoft has, naturally, made a relatively simple "look at this file and extract some information" workflow sound like an entire discipline.
