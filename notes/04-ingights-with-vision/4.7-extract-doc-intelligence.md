# Extract data with Azure Document Intelligence

## Module goal

Use **Azure Document Intelligence** to extract text, structure, tables, fields and other information from documents using **prebuilt or custom models**.

```text
Document
   ↓
Document Intelligence
   ↓
Model
   ↓
Structured data
```

## 1. What is Document Intelligence?

Azure Document Intelligence uses **OCR + deep learning** to extract information from documents.

It can identify:

- Text, including handwriting
- Key-value pairs
- Tables
- Selection marks
- Document structure
- Form fields
- Bounding boxes

### Three model categories

| Model | Purpose |
| --- | --- |
| **Document analysis** | Extract text, layout, tables and selection marks |
| **Prebuilt** | Extract data from common document types |
| **Custom** | Extract data from your own business-specific forms |

## 2. Read vs Layout models

### Read model

Extracts:

- Printed text
- Handwritten text
- Language
- Words and lines

```text
Document → Read → Text
```

Use it when you mainly need **text extraction** from documents without a predictable structure.

### Layout model

Extends Read with:

- Tables
- Selection marks
- Document structure
- Key-value pairs

```text
Document → Layout → Text + Structure + Tables
```

### 🔑 Exam distinction

> **Read = text**  
> **Layout = text + structure**

## 3. Document Intelligence Studio

The **Document Intelligence Studio** is the visual interface for:

- Testing Read/Layout models
- Testing prebuilt models
- Creating custom models
- Labelling documents
- Training models
- Testing custom models

Typical workflow:

```text
Upload documents
      ↓
Label fields
      ↓
Train
      ↓
Test
      ↓
Use model
```

For custom models, Microsoft recommends starting with **at least 5–6 sample forms**.

## 4. Prebuilt models

Prebuilt models require **no model training**.

Examples:

- Invoice
- Receipt
- Bank statement
- Check
- Pay stub
- Credit card
- Contract
- ID document
- US tax documents
- Mortgage documents

For example, an invoice model can extract:

```text
CustomerName
VendorName
InvoiceNumber
InvoiceDate
DueDate
Items
InvoiceTotal
```

### When to use prebuilt

If Microsoft already has a model for your document type:

> **Use the prebuilt model before building a custom one.**

Saves training data, time and money. Humanity occasionally gets to reuse something instead of rebuilding it from scratch. 🧠

## 5. Custom models

Use a custom model when your documents have **industry-specific or unique fields**.

There are two main custom extraction models:

### Custom template model

Best when the document has a **consistent layout**.

```text
Same layout
Same fields
Same positions
      ↓
Template model
```

Advantages:

- Fast training
- Lower cost
- Good for fixed layouts

### Custom neural model

Best when layouts **vary**.

```text
Different layouts
Different field positions
      ↓
Neural model
```

Advantages:

- Better with varying layouts
- Handles structured, semi-structured and unstructured documents
- Higher overall flexibility

Trade-off:

- Longer training
- Higher cost

### 🔑 Exam distinction

| Scenario | Model |
| --- | --- |
| Fixed/consistent layout | **Custom template** |
| Varying layouts | **Custom neural** |

## 6. Custom classifiers

A **custom classifier** determines **what type of document** you're dealing with before extraction.

```text
Incoming document
       ↓
   Classifier
       ↓
 ┌─────┼─────┐
Invoice Receipt Contract
   ↓       ↓       ↓
Model    Model    Model
```

Useful when an application receives **multiple document types**.

## 7. Composed models

A **composed model** combines multiple custom models.

```text
                Document
                   ↓
             Composed model
                   ↓
              Classify
            ↙    ↓     ↘
       Model A Model B Model C
```

The composed model determines which component model should process the document.

### Memory hook

> **Classifier = tells you what it is**  
> **Composed model = routes it to the right extractor**

## 8. Python SDK

Main client:

```python
DocumentAnalysisClient
```

Authentication:

```python
AzureKeyCredential
```

Example:

```python
document_analysis_client = DocumentAnalysisClient(
    endpoint=endpoint,
    credential=AzureKeyCredential(key)
)
```

Analyze a document from a URL:

```python
task = document_analysis_client.begin_analyze_document_from_url(
    model_id,
    formUrl
)

result = task.result()
```

### Key pattern

```text
begin_analyze_document_from_url()
             ↓
          task
             ↓
       task.result()
```

### 🔑 Exam traps

- **Read ≠ Layout**
  - Read → text
  - Layout → text + structure/tables/selection marks

- **Prebuilt ≠ Custom**
  - Prebuilt → common document type, no training
  - Custom → your own document type/data

- **Template ≠ Neural**
  - Template → consistent layout
  - Neural → varying layouts

- **Classifier ≠ extractor**
  - Classifier identifies the document.
  - Extraction model extracts its fields.

- **Composed model** combines multiple custom models and selects the appropriate one.

### 🧠 Memory hook

> **Read → Layout → Prebuilt → Custom → Classify → Compose**

Or, for the custom models:

> **Same shape = Template**  
> **Changing shape = Neural**  
> **Many document types = Classifier/Composed**
