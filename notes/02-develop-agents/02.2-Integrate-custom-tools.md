# Integrate custom tools into your agent

Built-in tools are useful, but they may not meet all your needs. In this module, learn how to extend the capabilities of your agent by integrating custom tools for your agent to use.

Learning objectives
By the end of this module, you'll be able to:

- Describe the benefits of using custom tools with your agent.
- Explore the different options for custom tools.
- Build an agent that integrates custom tools using the Microsoft Foundry Agent Service.

---

## Why Use Custom Tools

### **Purpose of Custom Tools**
- Custom tools extend an agent’s capabilities beyond built‑in functionality, enabling automation, accuracy, and tailored workflows.
- They allow agents to perform domain‑specific tasks that match business needs.

### **Core Benefits**
- **Enhanced productivity** — automate repetitive tasks and streamline workflows.
- **Improved accuracy** — consistent outputs reduce human error.
- **Tailored solutions** — address specific business processes and optimize outcomes. 
- Tools become available for the agent to use automatically when responding.

| Scenario | What the Agent Does | Outcomes |
| --- | --- | --- |
| **Healthcare Appointment Scheduling** | Integrates with scheduling systems and patient records; suggests appointment slots; sends reminders | Reduced admin workload; smoother scheduling; improved patient experience |
| **IT Helpdesk Support** | Connects to ticketing + knowledge base; troubleshoots issues; escalates complex cases; tracks ticket status | Faster issue resolution; reduced downtime; improved support efficiency |
| **E‑Learning & Training** | Integrates with LMS; recommends courses; tracks learner progress; answers content questions | Better learning outcomes; higher engagement; streamlined training workflows |

---

| Custom Tool Option | What It Is | What It Enables | Typical Uses |
| --- | --- | --- | --- |
| **Function Calling </>** | Describe function structure to the agent; agent selects and calls functions dynamically | Integrate custom logic and workflows in any language | Domain‑specific operations, business rules, internal processing |
| **Azure Functions** | Event‑driven serverless functions with triggers and bindings | Connect agents to external systems with minimal overhead | Automations, reacting to events, pulling/pushing data |
| **OpenAPI Specification Tools** | Connect agent to external APIs using OpenAPI 3.0 specs | Standardized, scalable API integration; auto‑generated client behavior | REST API calls, structured external data access |
| **Azure Logic Apps** | Low‑code/no‑code workflow automation | Connect apps, data, and services through visual workflows | Enterprise workflows, orchestration, multi‑system integration |

## Custom Tool Integration

### Key Takeaway
- You can integrate custom tools using **Function Calling, Azure Functions, or OpenAPI**.
- Each method includes a **tool definition, registration, and agent creation** step.
- **The agent automatically decides when to call tools** — you never manually invoke them.
- These integrations enable powerful, flexible, real‑time, domain‑specific agent capabilities.

### **Function Calling**
- Lets agents execute predefined functions dynamically based on user input.  
- Ideal for tasks like retrieving data, processing queries, or calling external APIs.  
- You define a function, register it as a tool, and the agent decides when to call it.

**Example: Python function + registration**

```python
import json

def recent_snowfall(location: str) -> str:
    mock_snow_data = {
        "Seattle": "0 inches",
        "Denver": "2 inches"
    }
    snow = mock_snow_data.get(location, "Data not available.")
    return json.dumps({
        "location": location,
        "snowfall": snow
    })
```

```python
function_tool = FunctionTool(
    name="recent_snowfall",
    parameters={
        "type": "object",
        "properties": {
            "location": {
                "type": "string",
                "description": "The city name to check snowfall for."
            }
        },
        "required": ["location"],
        "additionalProperties": False
    },
    description="Get recent snowfall totals for a given location.",
    strict=True,
)

tools = [function_tool]

agent = project_client.agents.create_version(
    name="snowfall-agent",
    definition=PromptAgentDefinition(
        model="gpt-4.1",
        instructions="You are a weather assistant tracking snowfall. Use the provided functions to answer questions.",
        tools=tools,
    )
)
```


### **Azure Functions**
- Serverless compute for real‑time or event‑driven workflows.  
- Agents can trigger Azure Functions via queues or HTTP.  
- Useful when your organization already uses Azure Functions for backend logic.

**Example: Queue-triggered Azure Function tool**

```python
tool = AzureFunctionTool(
    azure_function=AzureFunctionDefinition(
        input_binding=AzureFunctionBinding(
            storage_queue=AzureFunctionStorageQueue(
                queue_name="STORAGE_INPUT_QUEUE_NAME",
                queue_service_endpoint="STORAGE_QUEUE_SERVICE_ENDPOINT",
            )
        ),
        output_binding=AzureFunctionBinding(
            storage_queue=AzureFunctionStorageQueue(
                queue_name="STORAGE_OUTPUT_QUEUE_NAME",
                queue_service_endpoint="STORAGE_QUEUE_SERVICE_ENDPOINT",
            )
        ),
        function=AzureFunctionDefinitionFunction(
            name="queue_trigger",
            description="Get weather for a given location",
            parameters={
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "location to determine weather for"
                    }
                }
            },
        ),
    )
)

agent = project_client.agents.create_version(
    agent_name="MyAgent",
    definition=PromptAgentDefinition(
        model="gpt-4.1",
        instructions="You are a helpful weather assistant. Use the provided Azure Function to get weather information for a location when needed.",
        tools=[tool],
    )
)
```


### **OpenAPI Specification Tools**
- Allow agents to interact with external APIs using OpenAPI 3.0 specs.  
- Standardized, scalable, and ideal for REST API integration.  
- Supports anonymous, API key, and managed identity authentication.

**Example: OpenAPI JSON + registration**

```json
{
  "openapi": "3.1.0",
  "info": {
    "title": "get weather data",
    "description": "Retrieves current weather data for a location based on wttr.in.",
    "version": "v1.0.0"
  },
  "servers": [
    { "url": "https://wttr.in" }
  ],
  "paths": {
    "/{location}": {
      "get": {
        "description": "Get weather information for a specific location",
        "operationId": "GetCurrentWeather",
        "parameters": [
          {
            "name": "location",
            "in": "path",
            "required": true,
            "schema": { "type": "string" }
          },
          {
            "name": "format",
            "in": "query",
            "required": true,
            "schema": { "type": "string", "default": "j1" }
          }
        ]
      }
    }
  }
}
```

```python
with open(weather_asset_file_path, "r") as f:
    openapi_weather = jsonref.loads(f.read())

tool = OpenApiTool(
    openapi=OpenApiFunctionDefinition(
        name="get_weather",
        spec=openapi_weather,
        description="Retrieve weather information for a location.",
        auth=OpenApiAnonymousAuthDetails(),
    )
)

agent = project_client.agents.create_version(
    agent_name="openapi-agent",
    definition=PromptAgentDefinition(
        model="gpt-4.1",
        instructions="You are a weather assistant. Use the API to fetch weather data.",
        tools=[tool],
    )
)
```

### **Declarative Tool Behavior**
- You never write code to call tools directly.  
- The agent decides when to call a tool based on the user’s message.  
- Meaningful names + clear parameters help the agent choose correctly.
