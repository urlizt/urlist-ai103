# Microsoft Agent Framework (MAF) - Revision Page

## 1. What is MAF?

**Microsoft Agent Framework (MAF)** is Microsoft's current **code-first framework for building and orchestrating AI agents and agent workflows**.

It brings together the direction of Microsoft's earlier:

- **AutoGen** - focused heavily on multi-agent collaboration and orchestration.
- **Semantic Kernel** - focused on integrating AI models, tools, plugins, memory and application logic.

### Key exam/learning point

> **MAF is the strategic successor/unified direction for AutoGen + Semantic Kernel.**

For new Microsoft agent development, think **MAF**, rather than learning the older frameworks in depth.

---

## 2. Where MAF fits in Microsoft Foundry

Think of the layers like this:

```text
                    MICROSOFT FOUNDRY
                           |
          +----------------+----------------+
          |                                 |
     Prompt Agent                      Hosted Agent
     Declarative                       Code-first
          |                                 |
          |                         Microsoft Agent
          |                            Framework
          |                                 |
          +----------------+----------------+
                           |
                  Foundry Agent Service
                           |
              Hosting / Identity / Scaling /
                 Observability / Governance
```

### Prompt Agent

A more **declarative/configuration-first** approach.

You configure things such as:

- Model
- Instructions
- Tools
- Knowledge
- Agent settings

You don't need to build the orchestration logic yourself.

### Hosted Agent

A **code-first** approach.

You write the agent application yourself and Foundry provides the managed environment for hosting and operating it.

**MAF is particularly important here.** Microsoft recommends MAF as the orchestration layer for Foundry Hosted Agents.

# 3. MAF vs Foundry Workflows

This is the key distinction.

### Foundry Workflows

Historically provided a **visual/declarative way** to orchestrate agents and steps.

For example:

```text
Agent A
   |
   v
  IF
 /  yes  no
 |    |
 v    v
B     C
 \    /
  v  v
 Agent D
```

You define the workflow by configuring steps and connections.

### MAF Workflows

Provide the **code-first equivalent**.

Conceptually:

```text
Workflow
   |
   +-- Agent A
   |
   +-- Condition
   |
   +-- Agent B / Agent C
   |
   +-- Agent D
```

MAF lets you implement orchestration logic in code and provides workflow patterns such as:

- Sequential
- Concurrent
- Handoff
- Human-in-the-loop
- State/checkpoint handling
- Middleware
- Telemetry/observability

### Important current direction

Microsoft is retiring **Foundry Workflows on December 1, 2026** and is directing new workflow development toward **Microsoft Agent Framework**.

> **MAF is effectively the code-first successor to the Foundry Workflow approach.**

---

# 4. Why use MAF if Foundry already has agents?

Because the requirements can become much more complex than:

```text
User -> Agent -> Answer
```

A real application might look like:

```text
                 User
                   |
                   v
              Triage Agent
                   |
          +--------+--------+
          |                 |
          v                 v
    Billing Agent     Technical Agent
          |                 |
          +--------+--------+
                   |
                   v
              Review Agent
                   |
                   v
             Human approval
                   |
                   v
                Response
```

MAF gives you programmatic control over:

- Which agent runs
- When it runs
- What happens when it fails
- Whether agents run sequentially or concurrently
- How agents hand work to one another
- Where human approval happens
- How state is maintained
- How the whole process is traced

# 5. Agent vs Workflow

A very useful mental distinction:

> **An Agent decides dynamically what to do.  
> A Workflow defines the process it must follow.**

For example:

```text
Workflow
   |
   +-- Research Agent
   |      |
   |      +-- decides which tools to use
   |
   +-- Review Agent
   |      |
   |      +-- reasons about the research
   |
   +-- Approval step
```

So MAF applications can contain **both agents and workflows**.

---

# 7. The one-sentence mental model

> **Microsoft Foundry is the platform where you build, deploy, operate and govern agents; Microsoft Agent Framework is the code-first framework for programming the agents and their orchestration.**

Or even shorter:

```text
FOUNDry = PLATFORM
MAF     = CODE + ORCHESTRATION
```

---

# 8. MAF does not mean "Foundry only"

MAF can work with multiple model/provider ecosystems.

Conceptually:

```text
                    Agent Framework
                           |
          +----------------+----------------+
          |                |                |
       Foundry           OpenAI          Anthropic
          |
       Azure AI
```

So MAF is an **application/orchestration abstraction**, rather than simply another Foundry API.

# 9. What to remember for AI-103

### High-value concepts

1. **MAF = Microsoft Agent Framework**
2. It is Microsoft's current code-first agent/orchestration framework.
3. It brings together the direction of **AutoGen + Semantic Kernel**.
4. **Prompt Agents** are primarily declarative/configuration-first.
5. **Hosted Agents** allow you to build the agent application in code.
6. MAF is the recommended orchestration layer for **Hosted Agents**.
7. Foundry Workflows provided visual/declarative orchestration.
8. Microsoft is moving workflow development toward **MAF**.
9. An **Agent** reasons/decides dynamically.
10. A **Workflow** defines the process/orchestration.
11. MAF can contain both agents **and** workflows.
12. Foundry provides the managed production platform around the application.
